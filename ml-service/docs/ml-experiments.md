# ML Experiments: Transaction Categorization

This document records the experiments behind the ML-based transaction categorization in `ml-service`. Each experiment lists its setup, results and conclusions, so decisions can be traced back to measurements.

---

## Experiment 1: TF-IDF + Logistic Regression baseline

**Date:** 2026-10-15

### Goal

Measure how well a classic text classifier can assign a category to a bank transaction description, and in particular whether it can categorize transactions from merchants it has never seen.

### Data

- Synthetic dataset generated by `training/generate_data.py` (fixed seed `42`, fully reproducible).
- 4,400 rows: 11 categories × 400 rows each.
  - Expense: Groceries, Eating Out, Transport, Rent, Utilities, Entertainment, Subscriptions, Shopping, Health
  - Income: Salary, Other Income
- Each row is built from a real German merchant name and a typical German bank text pattern for its payment method (card payment, PayPal, SEPA direct debit, standing order, salary, refund), with random noise such as cities, dates, reference codes and customer numbers.
- Columns: `description`, `transaction_type`, `category`, `merchant`. The `merchant` column is not a model input. It is only used to group the cross-validation folds.
- No real or personal data is used.

### Preprocessing

Implemented in `app/preprocessing.py` and shared by training and the service, so the model always receives identically prepared input.

1. Lowercase the text.
2. Replace punctuation with spaces.
3. Remove reference codes (words of 8+ characters that contain both letters and digits).
4. Remove pure numbers (dates, store numbers, customer numbers).
5. Prefix the transaction type.

Example:

```
KARTENZAHLUNG REWE//FRANKFURT/DE 05.10.2026   (EXPENSE)
→ expense kartenzahlung rewe frankfurt de
```

### Model

A scikit-learn pipeline:

- `TfidfVectorizer(analyzer="char_wb", ngram_range=(3, 5))`: character n-grams of 3 to 5 letters within word boundaries, robust to spelling variants and glued-together bank text.
- `LogisticRegression(max_iter=1000)`

### Evaluation method

- `StratifiedGroupKFold` with 4 folds, grouped by merchant, shuffled with `random_state=42`.
- All rows of a merchant are always in the same fold, so every test fold contains only merchants the model never saw during training. This avoids leakage from near-identical rows of the same merchant.
- 4 folds because the smallest category (Salary) has 4 merchants.
- Metric: macro F1, which weights every category equally.

### Results

**Overall (unseen merchants):** macro F1 = **0.496 ± 0.075**, accuracy = 0.519

| Category | Precision | Recall | F1 |
|---|---|---|---|
| Salary | 1.000 | 1.000 | **1.000** |
| Other Income | 1.000 | 1.000 | **1.000** |
| Rent | 0.911 | 1.000 | **0.954** |
| Health | 0.868 | 0.542 | 0.668 |
| Groceries | 0.480 | 0.460 | 0.470 |
| Subscriptions | 0.519 | 0.383 | 0.440 |
| Utilities | 0.415 | 0.245 | 0.308 |
| Shopping | 0.187 | 0.642 | 0.290 |
| Entertainment | 0.602 | 0.163 | 0.256 |
| Eating Out | 0.335 | 0.170 | 0.226 |
| Transport | 0.137 | 0.107 | **0.120** |

### Analysis

The results split clearly into two groups.

**Categories with shared category words score high.** Salary ("gehalt", "lohn"), Other Income ("gutschrift", "erstattung", together with the "income" prefix), Rent ("miete", "dauerauftrag") and partly Health ("apotheke") contain words that appear across all of their merchants. The model recognizes these words even for merchants it has never seen.

**Categories identified only by the brand name score low.** For Transport, Eating Out, Entertainment, Shopping and Utilities, the only category-specific information is the merchant name. The surrounding words ("kartenzahlung", "paypal", "lastschrift", city names) appear in every category. A brand name the model has never seen, such as "ESSO" after training on "SHELL", "ARAL" and "UBER", shares no character patterns with the known names, so the model cannot infer its category.

**Shopping acts as a fallback class.** Shopping has high recall (0.642) but very low precision (0.187): when the model is uncertain, it tends to predict Shopping.

**Conclusion:** the model reliably learns category-specific vocabulary, but character-based TF-IDF cannot generalize to unknown brand names. This is a limitation of the method, not an implementation error. Grouping the folds by merchant made this limitation visible. A random split would have hidden it.

### Limitations

- The data is synthetic. Real bank texts are messier and may contain more category hints (for example "TANKSTELLE" or "STROM").
- The merchant-grouped evaluation is deliberately strict. In practice, most transactions come from merchants that already appear in the training data.
- Only one model has been evaluated so far.

### Next steps

1. Add an evaluation on known merchants (a stratified split without grouping) to measure performance in the common case, and report both numbers side by side.
2. Compare against the current keyword-based categorization. It is expected to score close to zero on unseen merchants.
3. Extend the dataset with more merchants per category and with realistic category words from real bank texts.
4. Evaluate sentence embeddings (multilingual MiniLM) + Logistic Regression, which may carry prior knowledge about brand names.
5. Test on hand-labeled real transactions (kept local, never committed).

## Experiment 2: Train/test split, hyperparameter tuning and error analysis

**Date:** 2026-10-15

### Goal

1. Tune the model's hyperparameters instead of using fixed values.
2. Measure performance on known merchants (the common case in the app) separately from unseen merchants (the hard case).
3. Understand which categories the model confuses on unseen merchants, using confusion matrices.

### Setup

Same synthetic dataset and preprocessing as Experiment 1 (4,400 rows, 11 categories × 400). The training script (`training/train.py`) now follows a classic train/test workflow:

1. **Train/test split:** 80/20 with `train_test_split`, stratified by category, `random_state=42` (3,520 training rows, 880 test rows).
2. **Hyperparameter tuning:** `GridSearchCV` with 5-fold cross-validation on the training data only, optimizing macro F1.

   | Parameter | Values tried |
   |---|---|
   | Character n-gram range | (2, 4), (3, 5) |
   | Regularization `C` | 0.1, 1, 10, 100 |

3. **Test evaluation:** accuracy, macro F1, training vs test accuracy (overfitting check), classification report and confusion matrix on the held-out 20%.
4. **Unseen-merchant evaluation:** 4-fold `StratifiedGroupKFold` grouped by merchant with `cross_val_predict`. Every merchant is held out exactly once, so every row gets a prediction from a model that never saw its merchant.
5. **Final model:** trained on all 4,400 rows with the best hyperparameters and saved to `models/model.joblib`.

A single `GroupShuffleSplit` was tried first for step 4 but rejected. Depending on which merchants landed in the test set, the score varied noticeably between runs on almost identical data (0.353 vs 0.381), and some categories (Rent, Salary) were missing from the test set entirely. Grouped cross-validation tests every merchant and every category, so the result is stable.

### Results

**Best hyperparameters:** n-gram range (2, 4), `C = 1`

| Evaluation | Macro F1 |
|---|---|
| Cross-validation on training data (known merchants) | 1.000 |
| Test set (known merchants, new text variations) | **1.000** |
| Unseen merchants (4-fold grouped CV) | **0.501** |

Training accuracy and test accuracy were both 1.000 (difference 0.000), so there is no sign of overfitting on known merchants.

**Per category, unseen merchants:**

| Category | Precision | Recall | F1 |
|---|---|---|---|
| Salary | 1.000 | 1.000 | **1.000** |
| Other Income | 1.000 | 1.000 | **1.000** |
| Rent | 0.901 | 1.000 | **0.948** |
| Health | 0.855 | 0.560 | 0.677 |
| Groceries | 0.370 | 0.425 | 0.396 |
| Subscriptions | 0.467 | 0.338 | 0.392 |
| Utilities | 0.364 | 0.240 | 0.289 |
| Entertainment | 0.561 | 0.185 | 0.278 |
| Shopping | 0.190 | 0.490 | 0.273 |
| Eating Out | 0.156 | 0.140 | 0.147 |
| Transport | 0.115 | 0.102 | **0.108** |

### Analysis

**Known merchants are solved.** On the random test split, every one of the 880 transactions was classified correctly. The model reliably ignores the noise around the merchant name (dates, reference codes, cities, payment wording) and recognizes the merchant from new text variations. This is the most common situation in practice.

**Unseen merchants remain the hard case.** The 0.501 result confirms Experiment 1 (0.496). The confusion matrix for unseen merchants shows where the errors go:

- **Shopping is the fallback class.** The model predicted Shopping 1,034 times, but only 196 of those were actually Shopping. Large shares of Eating Out (197), Groceries (162), Entertainment (152), Transport (129) and Utilities (106) ended up there. When the model does not recognize a brand, Shopping is its default guess.
- **Similar categories get mixed up.** Entertainment is often predicted as Eating Out (94), and Transport, Utilities and Subscriptions are confused with each other (for example Utilities → Transport: 106, Subscriptions → Transport: 78, Transport → Subscriptions: 81). These categories share the same payment wording (direct debit, PayPal), so without a known brand name the texts look alike.
- **The payment method acts as a shortcut.** 43 Health transactions were predicted as Rent. In the synthetic data, bank transfers ("UEBERWEISUNG", "DAUERAUFTRAG") only appear in Rent and Health, so for an unknown merchant the model associates "transfer" with Rent. This is a property of the generated data rather than of real-world banking, and needs fixing in the generator.
- **Category words generalize.** Salary, Other Income, Rent and most of Health stay strong because their texts contain words shared across all merchants ("gehalt", "gutschrift", "miete", "apotheke").

### Conclusions

- The model is ready for the common case: transactions from merchants it has seen before.
- For unseen merchants, the limiting factor is not the model settings (tuning changed little) but the information in the text. A brand name without context carries no category signal for a character-based model.
- One of the observed errors (transfers → Rent) is caused by the synthetic data design and should be fixed before drawing further conclusions.

### Next steps

1. Fix the transfer shortcut: add bank transfers to more categories in the generator.
2. Add more merchants per category and realistic category words (for example "TANKSTELLE", "STROM", "RESTAURANT") so the model can learn signals beyond brand names.
3. Use a confidence threshold in the service: when the model is unsure, fall back to the keyword rules or to Uncategorized instead of guessing Shopping.
4. Compare against the current keyword-based categorization.
5. Evaluate sentence embeddings (multilingual MiniLM) on the unseen-merchant setup.
6. Test on hand-labeled real transactions (kept local, never committed).
